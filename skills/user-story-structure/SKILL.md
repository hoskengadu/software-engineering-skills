# User Story Structure

Use this skill when a request needs to be transformed into a clear development item.

## Required Focus

- restate the problem in one sentence
- define the user value and expected outcome
- identify in-scope and out-of-scope items
- capture assumptions explicitly
- list dependencies and blockers
- define acceptance criteria that are observable and testable
- note risks, edge cases, and non-functional requirements when relevant

## Rules

- Do not invent business rules that were not provided.
- Prefer acceptance criteria that can be validated by behavior or tests.
- Flag ambiguous requirements instead of silently resolving them.
- Keep the story narrow enough to be implemented and reviewed safely.
